A small model that looks before it acts.

tth turns plain English into a shell command. It checks your real files in a read-only sandbox, then puts the command on your prompt. You decide whether to run it.

We're building it to run on a ~1.5B model in under 1 GB of RAM, and we aren't there yet. An open RL gym, where only software verifiers hand out rewards, tests every change to it.

What it promises

Three rules the model can't override.

  • It never runs your command.

    The command goes into your shell's input line. You press Enter, or you don't.

  • It checks your real files first.

    Probes run in a read-only, offline sandbox, with a 3 second limit and an 8 KB output cap. Secret paths are off limits.

  • It asks before anything leaves your machine.

    You see the exact text that would be sent, with secrets removed. The default answer is no.

The goal

Can a large model teach a small one how to think?

tth is a terminal agent that runs on a ~1.5B model in under 1 GB of RAM. When it can't verify a command, it asks a stronger agent, but only with your consent.

The research question is whether a large model's verified reasoning can make that small model better at terminal tasks that need reasoning, and whether chess practice adds anything. Training so far has only copied tool calls: 4 of 376 shell teacher turns contain any text. So the idea is untested, not failed.

How it works

One contract for tools. One handoff for help.

MCP is the single tool contract, so what we train on is what ships. A2A makes the expert swappable: a bigger model on your Mac, a machine on your network, or a cloud model. Neither one keeps you safe. That's the job of the sandbox, the classifier and the consent step.

What's built on MCP

  • Schema to grammarAvailable, and off by default. We measured it: same accuracy, ten times slower.
  • Verify, then commitBuilt. Staging tests the command first, and repeating a passing test commits it. The looping we measured is mostly gone.
  • Compiler toolsBuilt. The model fills in aggregate(file, op, column, where), and the tool writes and tests the awk or jq.
  • Domain packsNew capability arrives as a server with its own gym tasks, with no change to the core.

What's built on A2A

  • Answers you can checkBuilt. Typed results go through the same classifier and dry-run as the model's own commands.
  • Evidence with consentBuilt. An expert can ask for another probe, and you approve what goes back.
  • Expert tiersPlanned. Agent Cards route to a bigger local model before anything hosted.
  • Same handoff as trainingPlanned. The gym doesn't use A2A yet. The chess teacher will take over at a blunder through this handoff.
  • Escalation teachesPlanned. With your opt-in, a verified answer becomes a local lesson, so the same request needn't escalate twice.

The protocols don't make the model smarter on their own, and we haven't measured escalation improving results yet. Everything aimed at the model has to prove itself on the improvement ladder below, or it gets removed. Domain packs are still a plan.

The gym

Teacher, student, and a verifier neither can argue with.

Most of this project is an RL gym. Each environment hides its state behind tools, so the student has to look. Tool schemas are randomized, and errors are injected. Software assigns the reward: real execution for shell, python-chess and Stockfish for chess. A model never judges a model.

  1. Teacher reasonsA large model solves tasks in the gym and writes short reasoning for each step: goal, evidence, next check.
  2. Verifiers filterOnly correct episodes with no penalties survive.
  3. Student imitatesSupervised fine-tuning on the reasoning and the actions, then a quick smoke test before more GPU time.
  4. Teacher correctsThe student practises, including real chess. At a failure or blunder the teacher explains why and takes over, and the fix becomes new data (DAgger).
  5. Student exploresRL with verifier rewards, then a quantization matrix on the final model.

The improvement ladder

Each change is scored against the step below it, on the same held-out tasks, on the final quantized build on an 8 GB laptop. A change that doesn't win gets removed.

If the best student can't beat the best stock model under the size cap after at least 5,000 verified episodes, we stop training and ship the stock model. The safety layer and the gym stay useful either way.

Findings

What we measured, and what we got wrong.

Our first training run scored 0 out of 100. It looked like the model had forgotten everything. It hadn't. Training had taught it to end its turn before it learned the tag that opens a tool call, so it replied with nothing.

Where it stands now

Stock models on 100 held-out shell tasks, through the real gate, with no training. The best setup is Granite 4.1-3B with compiler tools, which beats the previous model by 40 points on the same tasks (95% interval 29 to 51). It uses about 2.6 GB of memory and takes a median of 15 seconds per task, so it misses our size and speed goals. A bake-off under the size cap will replace it.

How the first training run failed

  • Training hasn't beaten the untrained model yet.
  • It did change behaviour.
  • Chess shows no visible effect so far.
  • The recorded baseline can't be trusted.On these same 20 tasks the recorded base scored 0/20, and this run scored 7/20. The two differ in code version, backend and tools, so every number gets rerun.
  • Inference is the slow part.Episodes took 4.7 to 14.6 seconds with the model already loaded. So we deferred a Rust rewrite, which wouldn't speed that up. Fewer turns and shorter prompts will.
  • Only 90 examples, for 12 training steps.That's far too little to judge fine-tuning. It's why the ladder exists.

Read the full audit, including its limits. Small samples are labeled as small, and failures are reported as failures.
